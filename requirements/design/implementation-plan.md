## 🔴 R0安全弁との整合（2026-08-20・全フェーズの前提）

`.company/jobs/registry.yml` のローダ（`lib/job-registry.js`）は、**R0不変条件**として
「`safety.external:true`（対外アクション）のジョブは `schedule.kind:manual`（＝承認キュー経由）でしか
起動できない」を機械的に強制している（CLAUDE.mdの「外部アクションは承認必須」原則を全社自動化基盤に
ハードコードしたもの）。rebell-booksの**記事公開（git push→Cloudflare自動デプロイ→実サイト反映）は
この定義上「対外アクション」**に該当する。

**CEO最終決定（2026-08-20）: R0を維持する**。よって当初案（公開まで完全自動・事後報告のみ）は撤回し、
**「生成・二段階レビューまでは夜間cronで完全自動、実際の公開（push）はCEO承認を経る」の二段構成**に変更する。
同じ理由で、フェーズ4のアフィリリンク自動挿入（挿入後の再push）も同じ承認ゲートを通す
（挿入判断自体はAIが自動で行ってよいが、実行＝pushは承認後）。

```
[Job A: rebell-books-draft]                    [Job B: rebell-books-publish]
夜間cron・type:ai・safety.external:false         承認時のみ・schedule:manual・safety.external:true
選書→openBD実在確認→執筆→二段階レビュー           承認キューの記事を実際に publish.sh で
→ ローカルに draft:true で保存（git操作なし）      commit/push（＝ここで初めて対外発信）
→ .company/approval-queue.md に登録・Telegram通知  → 完了後 即時Telegram通知（公開URL付き）
```

この分離により、**手間のかかる「選書・執筆・品質チェック」は完全自動のまま**、CEOの負担は
「承認キューの記事をバッチで承認する」という軽いワンアクションだけに抑えられる（R0を一切崩さない）。
